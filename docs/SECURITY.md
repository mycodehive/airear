# 보안과 HTTPS

이 앱은 신뢰하는 개인 LAN에서만 사용합니다. 8자리 임의 PIN, IP에 묶인 12시간 토큰, IP당 분당 8회/전체60회 인증 시도 제한, 최대4 peer/64 auth session, same-origin 검증, LAN direct peer/Host 검사를 사용합니다. QR에는 주소만 포함됩니다. PIN 재생성 시 기존 세션/peer를 해제합니다. 관리 작업은 데스크톱 GUI 전용입니다.

주소 검사만으로 공용 네트워크 전체를 안전하게 만들지는 못합니다. 공유기 포트포워딩/UPnP/리버스프록시로 인터넷에 공개하지 마세요. VPN/게스트 Wi-Fi/공유 기기는 신뢰 범위에 포함하지 않는 것이 좋습니다. 앱은 프록시 전달 헤더로 클라이언트 IP를 신뢰하지 않습니다.

WebRTC 미디어는 DTLS/SRTP를 사용하지만 기본 HTTP의 PIN/토큰/SDP는 암호화되지 않습니다. HTTP는 신뢰 LAN에서 시험하기 위한 기본 모드입니다. 실사용 HTTPS 절차:

1. PC LAN IPv4를 DHCP 예약으로 고정합니다.
2. 해당 **IP SAN**을 포함한 서버 인증서와 PEM 개인 키를 준비합니다. 내부 CA를 사용한다면 CA 개인 키는 별도로 보관합니다.
3. iPhone이 내부 CA를 신뢰하도록 인증서 프로파일을 설치하고 설정 → 일반 → 정보 → 인증서 신뢰 설정에서 명시적으로 신뢰합니다. 조직 관리 기기는 관리자 정책을 따릅니다.
4. AirEar 설정에 인증서 PEM/키 PEM 경로를 지정하고 서버를 재시작합니다.
5. QR의 `https://LAN-IP:포트/`로 접속해 경고 없는 연결과 인증서 IP 일치를 확인합니다. 인증서 경고를 무시하는 방식은 검증 완료가 아닙니다.

앱은 인증서와 개인 키를 다운로드하거나 외부 서비스로 전송하지 않습니다. 개인 키 파일의 Windows ACL을 해당 사용자에게 제한하세요. 설정에는 키 내용이 아닌 로컬 경로만 저장합니다. DNS 이름은 현재 Host 검사에서 허용하지 않으므로 IP SAN 인증서를 사용합니다.

로그에 PIN/토큰/SDP를 기록하지 않고 aiohttp access log를 끕니다. OS 장치명·오류·LAN peer 주소는 진단 로그에 들어갈 수 있으므로 공유 전에 확인합니다. GitHub 업데이트는 HTTPS 및 SHA256을 사용하며 이 저장소의 정식 릴리스만 받습니다. 저장소 계정이 침해된 경우를 방어하는 별도 오프라인 서명키는 아직 없습니다.
